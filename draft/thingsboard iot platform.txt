----------------------------------------------------------------------
1. Data Modeling & Communication Protocol
----------------------------------------------------------------------

  MQTT Telemetry:
    ส่งข้อมูล Time-series ขึ้นหัวข้อ  v1/devices/me/telemetry  ในรูปแบบ JSON:

      {"temperature": 28.5, "vibration": 1.12}

  Attribute Scopes:

    - Client-side Attribute   : ฮาร์ดแวร์ส่งรายงานสถานะ (เช่น เฟิร์มแวร์เวอร์ชัน)
    - Shared Attribute        : ส่งค่าคอนฟิก (เช่น sampleRate) จากเว็บลงฮาร์ดแวร์
    - Server-side Attribute   : เก็บค่าเกณฑ์การแจ้งเตือน (threshold) ไว้บนเซิร์ฟเวอร์โดยอุปกรณ์มองไม่เห็น


----------------------------------------------------------------------
2. Multiplexed WebSocket API  (/api/ws/plugins/telemetry)
----------------------------------------------------------------------

  ใช้การเชื่อมต่อ WebSocket เพียงท่อเดียวเพื่อประหยัดทรัพยากร โดยส่ง Subscription Command รวม:

    {
      "tsSubCmds": [
        {
          "cmdId": 1,
          "entityType": "DEVICE",
          "entityId": "<YOUR_DEVICE_ID>",
          "keys": "temperature,vibration",
          "timeWindow": 60000
        }
      ],
      "alarmDataCmds": [
        {
          "cmdId": 2,
          "query": {
            "entityFilter": {
              "type": "entityList",
              "entityType": "DEVICE",
              "entityList": ["<YOUR_DEVICE_ID>"]
            },
            "pageLink": {
              "pageSize": 5,
              "sortOrder": {
                "key": {"type": "ALARM_FIELD", "key": "createdTime"},
                "direction": "DESC"
              }
            },
            "alarmStatuses": ["ACTIVE_UNACK", "ACTIVE_ACK"]
          }
        }
      ]
    }


----------------------------------------------------------------------
3. Two-Way Remote Procedure Call (RPC)
----------------------------------------------------------------------

  Endpoint : POST /api/plugins/telemetry/DEVICE/{deviceId}/rpc/oneway
  Headers  : X-Authorization: Bearer <JWT_TOKEN>
  Payload  : {"method": "setRelay", "params": true}

  จุดที่ต้องเน้นให้นักศึกษาตรวจสอบ:
    โค้ดฝั่งเว็บต้องมี Loading State และการดักจับ Timeout
    เพื่อป้องกันปัญหาคำสั่งค้างเมื่ออุปกรณ์ออฟไลน์


----------------------------------------------------------------------
4. Rule Engine & Alarm Rules
----------------------------------------------------------------------

  • การกำหนดเงื่อนไขใน Rule Chain:
    ดึงค่า threshold จาก Attribute มาเทียบกับ Telemetry ปัจจุบัน

  • หากเงื่อนไขเป็นจริง ระบบจะเข้าโหนด Create Alarm
    กำหนดระดับความรุนแรงเป็น CRITICAL
    และส่งข้อมูล Real-time Event ไปยังท่อ WebSocket ของหน้าเว็บทันที
