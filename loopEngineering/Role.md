## Frontend Design Standards

> The UI must look like it was **hand-crafted by a skilled designer** — not generated by AI. Every pixel matters.

### Visual Identity

- Use a **curated color palette** with HSL-tuned values — avoid raw primary colors (`#ff0000`, `#0000ff`)
- Define all colors, spacing, radii, shadows, and typography as **CSS custom properties** in `common.css`
- Use a **modern sans-serif font** from Google Fonts (e.g. `Inter`, `Outfit`, or `DM Sans`) — never rely on browser defaults
- Apply **consistent spacing rhythm** — use a base unit (e.g. `0.5rem` increments) for all margins and padding

### Layout & Responsiveness

- Design **mobile-first** — start with single-column layout, then enhance for wider viewports via `min-width` media queries
- Use **CSS Grid or Flexbox** for layout — never use tables, floats, or absolute positioning for structural layout
- All interactive elements must have a **minimum touch target of 44×44px** on mobile
- Test visual coherence at **320px, 768px, and 1280px** breakpoints

### Micro-Interactions & Polish

- Add **subtle transitions** (150–300ms ease) on hover, focus, and state changes — the interface must feel alive
- Buttons must have distinct **hover, active, focus, and disabled** states
- Use **smooth gradients or glass-morphism effects** where appropriate — avoid flat, lifeless surfaces
- Loading states must use **skeleton screens or animated spinners** — never leave a blank screen while data loads
- Error states must be **visually clear** (color + icon + message) — never show raw error strings or empty containers

### Anti-Patterns (Do Not)

- **Do not** use default browser form styling — all inputs, buttons, and selects must be custom styled
- **Do not** use generic placeholder text like "Lorem ipsum" — use realistic IoT-related labels
- **Do not** hard-code pixel values for font sizes — use `rem` or `em` relative units
- **Do not** leave `:focus` styles as browser defaults — provide visible, accessible focus indicators

## Backend & Security Standards

> The backend integration must be **accurate, resilient, and secure** — following zero-trust and defense-in-depth principles.

### API & Data Handling

- **Validate all API responses** before use — check HTTP status codes, verify expected JSON structure, handle `null`/`undefined` gracefully
- Wrap every `fetch()` and `JSON.parse()` call in **`try...catch`** — never let an unhandled exception crash the UI
- Implement **request timeouts** — do not let `fetch()` hang indefinitely; use `AbortController` with a reasonable deadline (e.g. 10s)
- Display **user-friendly error messages** — never expose raw API errors, stack traces, or internal server details to the user

### Authentication & Token Management

- Store tokens in **`sessionStorage` only** — never in `localStorage`, cookies, or global variables
- Implement **automatic token refresh** using the `refreshToken` — do not force re-login on every access token expiry
- **Clear all credentials on logout** — remove tokens, close WebSocket connections, and redirect to login
- Never log tokens, passwords, or secrets to `console.log()` — sanitize all debug output

### WebSocket Resilience

- Implement **Exponential Backoff Reconnect** on disconnect — delay 1s, 2s, 4s, ... up to max 30s
- **Clean up resources** on disconnect — call `ws.close()`, clear all event listeners, cancel pending timers via `clearTimeout()`
- Guard against **data inconsistency** — if incoming WebSocket data contains `NaN`, `null`, or out-of-range values, display a fallback state instead of corrupting the UI

### Security Rules

- **Zero-trust boundary inputs** — validate and sanitize every value received from the server before rendering in DOM
- Never use `innerHTML` with untrusted data — use `textContent` or DOM API methods to prevent XSS
- If a credential or token endpoint returns an unexpected status (4xx/5xx), **do not retry silently** — inform the user and log the decision to `DECISION.md`
